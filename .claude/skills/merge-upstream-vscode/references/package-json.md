version of a dependency in the same region of the file where Positron has
_added_ a dependency.

## Dependencies Positron has removed

The opposite case is easier to get wrong, because it does not always conflict.
Where Positron has _removed_ an upstream dependency, upstream still declares it,
so the merge can quietly restore the line -- and unlike a version bump, a
restored dependency looks like a normal part of the upstream diff.

This happened with `deemon`. #15264 replaced it with `@softwarenerd/deemon-ng`
and deleted the dependency; the 1.130.0 merge put it back. Both packages provide
a bin named `deemon`, so with both installed `npx deemon` resolved to a different
program in different checkouts of the same repo, and the build daemon scripts
silently used whichever one won (#15670).

The dependencies Positron has deliberately removed are listed in
`.removed-upstream-dependencies` at the repo root. Keep Positron's removal when
resolving the conflict. Hygiene fails if one of them reappears in the root
package.json, so `npm run precommit` will catch it -- but the list only covers
the root package.json, so check `remote/package.json`, `remote/web/package.json`,
and `build/package.json` by hand.

# package-lock.json

package-lock.json files are autogenerated, but if you compile without cleaning
up the merge conflicts, then node will ignore the lockfile and regenerate it,
which is not what we want. Clean up the merge conflicts in the lockfile as you
would for a package.json file.

Hand-resolving the lockfile is error-prone for `overrides`. When package.json
overrides a package with a local stub (e.g. `"sharp": "file:build/npm/stubs/sharp"`),
the resolved entry must be a top-level `node_modules/<pkg>` link. A merge can
instead leave the link nested under whichever package pulled the dependency in,
so the top-level entry is missing. `npm install` may not notice (it reports "up
to date" if node_modules already satisfies it), but `npm ci` fails with
`Missing: <pkg>@ from lock file`. The reliable fix is to regenerate rather than
edit: `npm install --package-lock-only`, then confirm with `npm ci --dry-run`.
